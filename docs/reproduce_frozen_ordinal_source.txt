Strict-frozen ordinal GTA source release: source identity and reproduction scope

This release adds a whole-classifier-frozen/eval implementation to the existing
public ordinal source. C_fixed uses c=0.4; D_fixed uses the original FP32 ordinal
projection p1+(2*p2+p3)/3. Both retain the same feature fusion, 256 interaction
parameters, auxiliary objectives, sampler, optimizer, schedule and native
evaluation. The reference configurations describe the fixed 2000-update recipe.
They are not a result, a preflight receipt or permission to launch training.

There are two distinct source identities:
 private executed39 manifest: 92b424a4141efd3d6e6184090fbb5b06f44b0c278345caf1391d3e517099ae10
 public mapped39 manifest:   21e35ab772ae791dd3fa30658b1d6a8f8178efb254332935847106523e2e9983
The machine-readable identity lists every private and public file digest.
Of the 39 files, 36 are byte-identical. The three mapped files change only an
existing output-origin label, inherited expected-source hashes and a provenance
docstring. Model, training, freezing, sampling, loss, optimization and evaluation
arithmetic are unchanged. All top-level functions/classes in the new frozen3
retain their private AST. The source map identifies the public bytes, not the
private bytes. A private CUDA QA receipt cannot certify this mapped source.

Source-only export, from the repository root:
 python -B tools/export_frozen_ordinal_source.py
The default verifies all 39 source bytes and the identity, prints a plan, imports
no model or Torch, opens no arrays/weights, queries no GPU and writes nothing.
To isolate code into a fresh directory:
 python -B tools/export_frozen_ordinal_source.py --output SOURCE39 --execute
The fresh SOURCE39 contains exactly 39 scientific source files. Sibling files
SOURCE39_source_manifest.json, SOURCE39_source_identity.json and
SOURCE39_export_receipt.json preserve their byte identities. The export receipt
is a source-binding check only; it is not model QA or a scientific preflight.
Reference configs remain in configs/frozen_ordinal_C_fixed.json and
configs/frozen_ordinal_D_fixed.json in the repository, outside the exact39 tree.

Before any formal reproduction, acquire separate engineering evidence for these
public bytes. The default QA command is inert:
 python -B SOURCE39/next_stage/frozen_ordinal_stage_checks.py --source-root SOURCE39 --source-manifest SOURCE39_source_manifest.json --source-manifest-sha256 21e35ab772ae791dd3fa30658b1d6a8f8178efb254332935847106523e2e9983
An actual authorized CUDA QA must use patch128, batch2, AMP, the original
7406a3ba7e5bac1a7d8ee24898cb954ff8576f37fcf5fba0e26ef9a2cb5c43e6
warmstart, --optimizer-update, --device cuda, --patch 128, --batch-size 2,
an explicit fresh --output, and --execute. It checks both C and D, strict load,
parameter/buffer/classifier identity, eval/BN/Dropout stability and real backward
and optimizer updates. A CPU64 check or code-only export cannot replace it.
This source package itself records no actual public model execution, CUDA QA,
formal training or dynamic-condition efficacy. Any later QA needs its own
source- and runtime-bound receipt and must not silently rewrite this identity.

Formal training remains default-inert. For example, a plan can be inspected with
 python -B SOURCE39/next_stage/frozen_ordinal_stage_train.py --config configs/frozen_ordinal_C_fixed.json --manifest INPUT_MANIFEST --output FRESH_RUN
Use D_fixed's config for the paired dynamic plan. The actual --execute path
requires a full39 source map, a newly acquired public-source CUDA QA/preflight,
verified input bytes, the original warmstart and a separately identified
prospective protocol with frozen gates. Do not transplant private protocol,
runtime, bank, preflight or execution receipts into a public-source experiment.
The fixed warmstart hash is an identity requirement, not a checkpoint step.
This package bundles no weights, CT, labels, predictions, private runtime
receipts or credentials. If the original warmstart is unavailable, reproducing
a different initialization is a different declared experiment, not an exact
rerun obtained by bypassing source or weight identity checks.

This release prepares a reproducible implementation. It does not establish that
dynamic conditioning improves AVT, choose a next candidate, or reinterpret prior
negative results. Scientific conclusions require the separately frozen actual
utility and same-weight correspondence tests.

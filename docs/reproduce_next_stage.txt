GTA-AVT next-stage implementation: revised source reproduction notes
Date: 2026-10-23

Scope and status

This is a documentation revision plus byte-identical diagnostic-source additions
for the frozen next-stage scientific source overlay. It is not a new experiment identity or a new algorithm version.
No original scientific source, old configuration value, run inventory or checkpoint has
been rewritten by this revision. No data, weights or execution infrastructure is
included. The historical minimal4 study remains a separate completed study.

The frozen readout and the fixed 96-patch local oracle both failed their
prospective gates. The raw local A proposal is STOPPED. Neither formal L0 nor
formal Lp training was launched. Its implemented files/configurations remain
for traceability, not as evidence of completed or approved experiments.
Read the negative report at reports/next_stage_diagnostics_20261023/readout.txt.
A cold, unadapted oracle failure does not refute all learnable GTA implementations;
it does not authorize a new normalization, oracle variant or long run either.

The 2000-update Kp/Gp GDF pair completed its fixed budget and failed its screening
gate; independent numerical and scientific review agrees. The complete eight-case
record is reports/next_stage_GDF_VAL_20261023/readout.txt.
U/K is still running. No final U/K result or completed whole-stage claim is made.
The new global preflight actually passed CUDA128, batch2, FP32+AMP checks
on an isolated 47-source snapshot, after fully hashing 144 TRAIN input/target
files. This is implementation evidence, not a scientific benefit or complete
checkpoint replay. See reports/next_stage_engineering_20261023/README.txt.

Apply next_stage/ and this documentation to a clean copy of the existing public
repository whose code/ files match next_stage/source_identity_20261023.json. This overlay intentionally
does not duplicate code/. All 24 required code/ files were compared byte for byte
with the public checkout and the frozen deployment inventory. Of the original
22 next_stage/ artifacts (21 Python and one gate JSON), 21 retain exact bytes.

The trainer inventory selects 45 files; it omits that gate JSON. These are
related but different inventory scopes, not two contradictory source counts.
No public checkout was changed while preparing this source/documentation revision.

The six public configuration copies change only the descriptive role string to
remove machine identifiers. Their scientific values remain identical to the
source configurations; both hashes and the changed field are in next_stage/source_identity_20261023.json.
Use a clean output directory for every run. Do not resume from a different source
inventory, different data identity, or different initialization.

The new source release index identifies the original artifacts and the later
diagnostic/QA additions separately. It is not the immutable scientific inventory saved
in an old run/checkpoint. Do not replace old experimental source identities with

Later diagnostic additions and exact-replay limits

Four additional artifacts reproduce the implemented completed diagnostics:
local_oracle_probe.py, local_oracle_probe_checks.py, local_oracle_gate_20261023.json
and gdf_scale_audit.py. Their bytes match the actual diagnostic implementations.
They extend the source release; they do not change the historical 22+24 inventory

administrator or original execution record is added.

The local oracle is default-plan-only, but importing it still needs NumPy.
Its plan, old common weight and readout-head identities are pinned to the actual
experiment. The original plan, private cache manifests and trained weights are
not supplied; exact model replay is therefore unavailable from these sources
alone. Do not patch a SHA or fabricate a passed record to impersonate that run.
A newly generated plan/initialization is a different prospectively declared
experiment. The public numeric report can be recomputed without these artifacts.

Its default plan reads metadata, not patient arrays or weights; --execute is a
separate explicit action. The GDF audit is also metadata-plan-only by default,
requires genuine local input/producer manifests, and reads selected TRAIN nodes

publishing source files. Neither default is a portable global training QA pass.

Reference environment

The observed reference environment used Python 3.8.10, Torch 1.11.0+cu113,
NumPy 1.22.4, SciPy 1.10.1, scikit-image 0.21.0, and SimpleITK 2.3.1.
requirements_next_stage_reference.txt records primary pins; it is not a complete
transitive lock or a guarantee of bitwise CUDA training. Install the matching
Torch build separately for a compatible local GPU/driver. The repository's older
default requirements describe another environment and must not be presented as
the same reference runtime.

The normal scientific path needs NumPy, SciPy, scikit-image, SimpleITK and Torch.
No remote-login package is required by this overlay. CPU fixture checks can help
verify definitions; full 128-cubed, batch-two integration checks should also run
in the actual reference GPU environment before any long experiment.

GDF preparation and its limited interpretation

GDF uses the exact cumulative sum of radius-scaled centerline Gaussians in
physical millimeters, followed by log1p and one TRAIN-derived equal-case RMS
scale. It does not replace the sum with nearest-centerline or max-Gaussian
fields. The scale is fitted once on TRAIN and frozen; it is not normalized
independently by each case maximum. Background values are zero under the target
definition. This auxiliary supervision is not a topology-preservation theorem.

First inspect storage and freeze a source-bound probe, then generate targets:

  python next_stage/prepare_gdf.py --manifest cache/manifest.json --cache-root cache --output gdf_train --probe-file gdf_train/probe.json --backend cuda --max-output-bytes 6442450944 --probe-only
  python next_stage/prepare_gdf.py --manifest cache/manifest.json --cache-root cache --output gdf_train --probe-file gdf_train/probe.json --backend cuda --max-output-bytes 6442450944 --execute

The 6GiB output cap is a storage budget, not promised free space or runtime.
Review the probe's actual required bytes and reserve before execution. CPU
fallback, if explicitly permitted, must be reported as CPU. Dense targets and
their manifest stay local. Preparation and numerical verification cannot prove
that a GDF-supervised segmentation model has a performance advantage.

Experiment configurations and attribution

U_random10000.json / K_random10000.json: same constant-condition architecture,
random initialization and 10000-update budget; old global auxiliary weights are
0/0 versus .1/.1. This pair tests attribute supervision, not dynamic consumption.

Kp_warm2000.json / Gp_warm2000.json: same historical constant initialization,
optimizer reset, 2000-update budget and global auxiliary supervision; only GDF
weight changes from 0 to .1. Both consume the same target metadata. A warm-start
comparison does not erase the supervision present in the inherited checkpoint.

L0_local2000.json / Lp_local2000.json: same historical constant initialization,
same fitted FP32 local-head initialization, local soft-CE .1, old global auxiliary
weights .1/.1, GDF weight0, and 2000 updates. Both compute local logits and backprop
localCE into the shared classifier. Only detached condition consumption differs.
LocalCE is each patch's valid-window mean followed by the whole batch mean;
zero-support patches contribute zero and retain their place in that denominator.
The local window is16mm at1mm, stride4, and retains the original radius bins.
Lp introduces the condition after500 successful updates over500 further updates;
the1000th successful update reaches alpha1. q0=.2 and the original GAAM arithmetic
remain fixed; SAAM uses a uniform condition. This raw pair was STOPPED after the failed fixed oracle.
No formal L0/Lp training result exists; these configurations are implementation
records and must not be auto-launched by reproduction documentation.

All recipes keep train/inference patch128, batch2, fixed endpoint selection and
the original AMP retry/update safeguards. No best-validation checkpoint is selected.
The extra local_model.py/local_checks.py represent the earlier frozen-readout
implementation and its contracts. They do not mean a second local training arm
has been tested or approved.

Commands without --execute only inspect training plans, for example:

  python next_stage/stage_train.py --config next_stage/configs/U_random10000.json --manifest cache/manifest.json --output runs/U

Missing prerequisites for exact endpoint reproduction

1. No historical constant checkpoint is bundled. The exact historical byte hash
   must be verified if a separately released checkpoint becomes available. A
   retrained checkpoint is a new experimental origin and must be identified as
   such; it cannot silently substitute for historical weights in an exact claim.

2. No fitted local-readout endpoint is bundled. frozen_readout.py and
   frozen_readout_fit.py can generate one from the specified common checkpoint
   and TRAIN-only fit/probe bank. Use frozen_readout_gate_A_init_20261023.json;
   record the plan SHA, CPU64 solver endpoint/convergence, and actual FP32 weight
   SHA. The readout probe holds out labels within TRAIN, not completely unseen
   segmentation-training patients; it is not a zero-shot test. A gate result
   cannot auto-launch a segmentation study.

3. portable_preflight.py is now supplied for the GLOBAL trainer only. It
   generates a passed receipt only after actual TRAIN byte/geometry/target
   checks and observed CUDA model/synthetic sampler passes. The public source
   inventory is a superset of the actual 47-file QA snapshot: the scientific
   dependencies are byte-identical, but whole inventories are not identical.
   Run the preflight on your actual source/data/runtime. Cache overrides must
   equal trainer-consumed paths; relocation requires explicit local manifest
   generation. No local-learning receipt or private queue launcher is supplied.
   Genuine weight/manifest prerequisites still apply; never fabricate receipts.

4. The local oracle has completed and failed its registered screening gate.
   Raw local A is stopped, not deferred awaiting another oracle. The completed
   readout/oracle/GDF-field diagnostics are separately reported at
   reports/next_stage_diagnostics_20261023/readout.txt. Their original experiment
   identities stay unchanged. GDF fixed-endpoint segmentation evidence passed
   independent arithmetic review, with its negative gate retained; U/K remains in progress. This documentation
   adds no new performance, stability or zero-shot claim.

Raw data, weights, machine-specific receipts and unpublished manuscripts must
remain outside a source publication. Actual evaluation still needs original CT
metadata for native-grid restoration. Engineering reproducibility and scientific
effectiveness are separate requirements.

Portable GLOBAL preflight commands

From the combined repository root, the default command only prints a metadata plan:

  python next_stage/portable_preflight.py --project . --manifest cache/manifest.json --output checks/global_preflight --gdf-root gdf_train --gdf-sample-points 8

Add --execute to run real validation. Omit --gdf-root for random U/K recipes
without GDF targets. A fresh output directory is required. --python selects
the model/sampler child interpreter; it must use the intended reference runtime.
After actual success, pass checks/global_preflight/receipt.json through the
global trainer --preflight-receipt option and separately add --execute to
that training command. Warm-start recipes additionally need genuine --warmstart
and --warmstart-sha256 arguments. No command here resumes the stopped local A.
